css-oidc-login vocabulary

Terms a WebID profile uses to accept authentication by one subject at one external OpenID Connect provider.

Used by css-oidc-login, a login method for the Community Solid Server that authenticates people against an external OpenID Connect provider.

A profile states the acceptance in a single grant node: an issuer alone grants nothing, and neither does a subject identifier. Removing the node revokes external login for that person and nobody else.

Terms

external login

https://tophcodes.github.io/css-oidc-login/ns#externalLogin

Relates a WebID to a grant node carrying one issuer and one subject identifier. The statement's subject is the person's own WebID. A profile may carry several grants, one per provider.

issuer

https://tophcodes.github.io/css-oidc-login/ns#issuer

The issuer identifier of the provider a grant applies to, as an IRI. Compared against the token's iss claim, ignoring a trailing slash. A literal does not satisfy it.

subject identifier

https://tophcodes.github.io/css-oidc-login/ns#subject

The subject identifier the provider assigns to this person, as a literal. Compared exactly against the token's sub claim. This is what makes a grant name a person rather than a provider: without it, anyone able to obtain a token from the same issuer would inherit the grant.

Notes

These IRIs are identifiers. The server compares them as strings and never dereferences them, so this page is documentation rather than something the software fetches. A deployment preferring its own vocabulary can configure a different predicate for the first term; the two inside the grant node are fixed.

The grant must sit in the profile's default graph, with the person's own WebID as subject. A statement about somebody else, one parked in a named graph, and an issuer written as a quoted string are each refused — they place the issuer's name near the WebID without asserting anything about it.
