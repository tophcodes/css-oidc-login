css-oidc-login vocabulary

Three terms used by css-oidc-login, a login method for the Community Solid Server that authenticates people against an external OpenID Connect provider.

A WebID profile uses them to state that its owner accepts being authenticated by one particular subject at one particular provider. Both halves sit in a single grant node: an issuer alone grants nothing, and neither does a subject. Removing the node revokes external login for that person and nobody else.

Terms

externalLogin
https://tophcodes.github.io/css-oidc-login/ns#externalLogin
Relates a WebID to a grant node. The subject is the person's own WebID; the object is a node carrying exactly one issuer and one subject identifier. A profile may carry several, one per provider.
issuer
https://tophcodes.github.io/css-oidc-login/ns#issuer
The issuer identifier of the OpenID Connect provider the grant applies to, as an IRI. Compared against the iss claim of the ID token, ignoring a trailing slash. A literal here does not count.
subject
https://tophcodes.github.io/css-oidc-login/ns#subject
The subject identifier that provider assigns to this person, as a literal. Compared exactly against the sub claim. This is what makes the grant name a person rather than a provider: without it, anyone able to obtain a token from the same issuer would inherit the grant.

Notes

These IRIs are identifiers. The server compares them as strings and never dereferences them, so this page is documentation rather than something the software fetches. A deployment preferring its own vocabulary can configure a different predicate for the first term; the two inside the grant node are fixed.

The grant must be in the profile's default graph, with the person's own WebID as subject. A statement about somebody else, one parked in a named graph, or an issuer written as a quoted string are each refused — they place the issuer's name near the WebID without asserting anything about it.

Also available as Turtle.
